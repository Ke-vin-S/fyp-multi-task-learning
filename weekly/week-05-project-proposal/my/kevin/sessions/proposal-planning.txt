     Diagram needed: Mermaid from 02-gbc-architecture.mmd

     - Why: Formal conditional independence, visualizable dependency graph

❯ why did you add grad tag not to mtrl                                          

● Good catch. Two reasons:

  1. PMR already covers the MTRL territory. PMR uses a learned precision matrix
  Omega (Cholesky-parameterized) that directly encodes task relationships — this
   is the same core mechanism as classical MTRL (Zhang & Yeung, 2010), just with
   a different loss formulation (MSSL vs. matrix-variate normal prior). Adding
  another MTRL variant as Architecture 4 would be redundant.
  2. Grad-TAG is a different mechanism entirely. It discovers task groupings
  from gradient signals (dynamical affinity) rather than from learned parameter
  covariance (statistical affinity). It complements rather than duplicates the
  existing three architectures. But you raise a fair point — Grad-TAG is more of
   a diagnostic/analysis tool than an architecture itself. Listing it as
  Architecture 4 Candidate 2 is a stretch.

  Would you like me to revise Architecture 4's candidates? A cleaner framing
  would be to keep the four real architecture candidates (Low-Rank,
  Kanakis/MTI-Net cross-task attention, Recon layer splitting, or a
  Decomposition method) and reposition Grad-TAG as a pre-training analysis step
  in the Methodology — which is actually how it was described in the week-04
  integration docs.
