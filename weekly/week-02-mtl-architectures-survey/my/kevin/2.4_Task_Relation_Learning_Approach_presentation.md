## Slide 2: What is Task Relation Learning?

**In MTL, tasks are related — but how do we express "relatedness"?**

The task relation learning approach answers this by **quantifying the relationship between every pair of tasks as a number**, and then learning those numbers from data.

Think of it as building a **social network of tasks**:
- Some tasks are close friends — they share a lot (similar weights)
- Some are acquaintances — they share a little
- Some are strangers — no sharing at all

The output is a **task similarity table** Ω that tells you, for every pair, how strongly their parameters should be coupled.

**Why this exists:**
Not all tasks are equally related. In speech:

```
Keyword Spotting ←→ Speaker ID      (both use voice characteristics)
     │                                       │
     │            weaker link                 │
     │                                       │
     └───────── Emotion Recognition ─────────┘
```

KS and SID are both about voice patterns → strong coupling makes sense. ER involves affective cues that may conflict with both → weaker coupling. **Task relation learning discovers these patterns automatically.**

**Key distinction from other approaches:**
- Low-rank (2.2): "the whole table of weights is simple" — one global property
- Task clustering (2.3): "tasks belong to groups A, B, or C" — discrete buckets
- **Task relation (2.4): "KS and SID are 0.72 similar, KS and ER are 0.15 similar"** — per-pair, continuous

> **Speaker notes:**
> - This is the most flexible parameter-based approach. It doesn't force tasks into discrete groups, and it doesn't assume one global structure. Each pair gets its own similarity score.
> - The analogy to social networks is useful: some friends are close, some are acquaintances, some are strangers. Task relation learning discovers this graph.
> - The approach is also the most interpretable — you can visualize Ω as a heatmap and immediately see which tasks cluster together.

## Slide 3: Mechanics — How Ω Works with Model Parameters

**Learn a quantitative pairwise task similarity matrix Ω from data, rather than assuming it.**

- Earlier work: task relations were **pre-specified** from domain knowledge (e.g., "this tree structure defines which tasks are related")
- Task relation learning: **Ω is an optimization variable**, learned jointly with model parameters
- The regularizer couples tasks proportionally to their learned similarity

```
Given: m tasks, each with parameter vector w_i ∈ ℝᵈ
Learn:  W = [w₁ ... w_m] ∈ ℝᵈˣᵐ   (model parameters)
        Ω ∈ ℝᵐˣᵐ                 (task covariance matrix)

Intuition: If Ω_ij is large → w_i and w_j are penalized for being different
           If Ω_ij ≈ 0    → w_i and w_j train almost independently
```

> **Speaker notes:**
> - This is the most flexible of the parameter-based approaches. Low-rank imposes a global rank constraint; clustering forces hard group assignments; task relation learning allows a continuous spectrum of per-pair similarities.
> - Ω is a covariance matrix (positive semidefinite), not a correlation matrix. The raw values are scale-dependent; for interpretation you'd normalize to correlation: ρ_ij = Ω_ij / sqrt(Ω_ii · Ω_jj).
> - The key challenge: Ω has O(m²) parameters. For many tasks this becomes expensive — later work adds sparsity (ℓ₁ on Ω) to handle this.

## Slide 4: The Starting Point — Pre-specified Task Relations

Before anyone learned task relations from data, they were **hand-coded as prior knowledge**.

| Approach | How Relations Are Given | Mechanism | Ref |
|----------|------------------------|-----------|-----|
| **Uniform similarity** | All tasks equally related | Each `w_i` pulled toward the **global mean** `w̄ = (1/m) Σ w_j` | [69, 70] |
| **Known pairwise weights** | Domain expert provides `s_ij` for each pair (i,j) | Regularizer: `Σ s_ij · ‖w_i - w_j‖²` — the larger `s_ij`, the more `w_i ≈ w_j` | [71, 72] |
| **Tree structure** | Tasks organized in a known hierarchy | Each task's parameters pulled toward its **parent node** in the tree | [75] |

```
Example with known pairwise weights:
  Expert says: KS↔SID similarity = 0.8,  KS↔ER similarity = 0.3,  SID↔ER similarity = 0.1

  Regularizer = 0.8‖w_KS - w_SID‖² + 0.3‖w_KS - w_ER‖² + 0.1‖w_SID - w_ER‖²
  → KS and SID forced close, ER allowed to drift
```

**The problem**: domain experts don't actually know these numbers. Wrong `s_ij` → wrong regularization → worse than single-task.

> **Speaker notes:**
> - [69] Evgeniou et al. (2004) assumed every task's parameters should gravitate toward a shared mean. This is the simplest possible parameter-based MTL — one global coupling strength for everything.
> - [71] Evgeniou et al. (2005) generalized to task-specific coupling: if two tasks are known to be related (e.g., two object recognition tasks from similar domains), give them larger `s_ij`.
> - [75] Kato et al. (2007) exploited taxonomic hierarchies (e.g., ImageNet's class tree) — a child node inherits similarity to its parent, forming a directed acyclic graph of task relations.
> - The fundamental limitation of all these: they **cannot correct wrong assumptions**. If the expert thinks KS and ER are unrelated but data says otherwise, the model is locked out of that signal.
> - This is the gap that MTGP fills — eliminate the need for expert-specified task relations entirely.

## Slide 5: Foundational Methods — MTGP

**Multi-Task Gaussian Process** — Bonilla et al. (2007)

A Gaussian Process prior is placed over the latent functions:
```
f ~ N(0, Σ)

where  cov(f_i(x), f_j(x')) = Ω_ij · k(x, x')
       ────────   ────────
       task cov    instance kernel
```

- `f_i(x)`: latent function value for task i at input x
- `k(x, x')`: standard kernel (RBF, Matern) that measures instance-level similarity
- `Ω_ij`: task-level covariance — how much do outputs of task i and task j covary?

**Learning Ω**: maximize the marginal likelihood (integrate out f, optimize Ω via gradient ascent).

> **Speaker notes:**
> - The product form `Ω_ij · k(x, x')` decomposes similarity into task-level × instance-level. This is sometimes called the "linear model of coregionalization" (LMC) in geostatistics.
> - Ω must be positive definite to ensure Σ is a valid covariance matrix — this constraint is built into the marginal likelihood optimization.
> - Limitation: Ω is a point estimate (single matrix). Overfitting risk when tasks are few and data is noisy. This motivates the Bayesian extension (MTGTP).

## Slide 6: Bayesian Extensions — MTGTP

**Multi-Task Generalized t-Process** — Zhang & Yeung (2010)

Places a **prior on Ω itself** to account for uncertainty:
```
Ω ~ Inverse-Wishart(ν, C)
```

- `ν`: degrees of freedom (controls prior strength)
- `C`: base covariance matrix — can be estimated from data using Maximum Mean Discrepancy (MMD) between task distributions

Integrating out Ω yields a **t-process** (heavier tails than Gaussian) → more robust to outliers.

> **Speaker notes:**
> - The inverse-Wishart is the conjugate prior for covariance matrices of multivariate Gaussians. Choosing it makes the math tractable — marginalizing over Ω gives a multivariate t-distribution for the function values.
> - Heavier tails = model is less sensitive to individual data points that deviate from the pattern. Important when tasks have varying amounts of clean data.
> - The MMD-based initialization of C is noteworthy: it pre-computes task similarity from raw features (distribution-level), giving the model a reasonable starting point before finetuning.

## Slide 7: Central Method — MTRL

**Multi-Task Relationship Learning** — Zhang & Yeung (2010, 2012)

The most influential formulation in this approach. Places a **matrix-variate normal prior** on W:

```
W ~ MN(0, I, Ω)

where:  I    = row covariance (d×d, identity = features are independent)
        Ω    = column covariance (m×m, task covariance matrix)
```

Joint optimization over both W and Ω:
```
min   L(W, b) + λ₁‖W‖²_F + λ₂ tr(W Ω⁻¹ Wᵀ)
W,Ω

s.t.  Ω ≻ 0         (positive definite)
      tr(Ω) ≤ 1     (bounded complexity)
```

> **Speaker notes:**
> - This problem is **jointly convex** in W, b, and Ω — global optimum is guaranteed. This is a major advantage over MTGP where the marginal likelihood is non-convex.
> - The `tr(W Ω⁻¹ Wᵀ)` term is the key. Expand for intuition: each column w_i of W (task i's parameters) is pulled toward the weighted average of other tasks' parameters, with Ω determining the weights.
> - Relationship to Mahalanobis: `w_iᵀ Ω⁻¹ w_j` is a Mahalanobis-like inner product. Tasks with high Ω_ij have small effective distance.
> - A notable property: given Ω, the optimization over W decouples into m independent problems → parallelizable.
> - This formulation has been extended to multi-task boosting (Zhang 2010b), multi-label learning (Zhang 2010c), and multi-output regression (Rai 2012, Rakitsch 2013, Goncalves 2016).

## Slide 8: Extensions of MTRL

| Extension | Key Idea | Citation |
|-----------|----------|----------|
| **Sparse task relations** | ℓ₁ regularization on Ω → only the most important pairwise relations survive | Zhang et al. (2017) |
| **High-order relations** | `(WᵀW)ᵗ ~ Wishart(0, Ω)` — captures beyond-pairwise inter-task structure | Zhang & Yeung (2013) |
| **Feature-level** | Matrix-variate generalized normal prior → simultaneous feature selection + task relation learning | Zhang et al. (2010, 2014) |
| **Block sparse** | Symmetric matrix-variate generalized hyperbolic prior → discovers block structure in W | Archambeau et al. (2011) |
| **Low-rank Ω** | Matrix generalized inverse Gaussian prior → Ω is low-rank (few latent factors drive all task similarities) | Yang et al. (2013) |
| **Deep MTL** | Tensor-variate normal prior on parameter tensors in FC layers | Long et al. (2017) |
| **kNN variant** | Learns an asymmetric task similarity matrix S in a local (nearest-neighbor) framework | Zhang (2012) |

> **Speaker notes:**
> - The sparsity extension (ℓ₁ on Ω) is practically important: for m=100 tasks, Ω has ~5000 free parameters. ℓ₁ prunes this to only the meaningful edges.
> - High-order extension: the standard formulation couples pairs (i,j). The power-t generalization captures multi-way structure — e.g., tasks {1,2,3} collectively form a subspace even if no single pair is strongly correlated.
> - The kNN variant (Zhang 2012) is philosophically interesting because it treats task similarity as *asymmetric* — task A can help task B more than B helps A (like an expert helping a novice).
> - Long et al. (2017) brings this to deep learning: instead of a 2D matrix Ω, uses a tensor normal prior over the full parameter tensor of the last shared layers.

## Slide 9: The MTRL Regularizer — Intuition

Why does `tr(W Ω⁻¹ Wᵀ)` enforce task relationship learning?

```
Case 1: Ω = I (identity) → Ω⁻¹ = I
  tr(W · I · Wᵀ) = ‖W‖²_F
  → standard ℓ₂ regularization, no task coupling

Case 2: Ω has off-diagonal structure
  If Ω_ij is large → Ω⁻¹_ij is small
  → w_i and w_j are encouraged to be similar
  → training data from task j regularizes task i

Case 3: Block diagonal Ω
  → tasks form independent groups
  → within-group coupling, between-group independence
```

The learned Ω reveals the **intrinsic task structure** — no need to pre-specify clusters or hierarchies.

> **Speaker notes:**
> - The convexity of formulation (21) is what makes MTRL practical. Earlier methods (MTGP) had non-convex marginal likelihoods with multiple local optima.
> - Note the constraint `tr(Ω) ≤ 1`: without it, Ω could shrink arbitrarily (since smaller Ω means larger Ω⁻¹, which means stronger regularization — the model would just push Ω → 0 and over-regularize). The trace constraint prevents this degeneracy.
> - In practice, Ω often reveals interpretable structure: tasks from the same domain (e.g., all NLP tasks) show high pairwise similarity, while cross-domain pairs show near-zero entries.

## Slide 10: Probabilistic Perspective

All methods in this section derive from **hierarchical Bayesian models**:

```
Level 1:  y_ij | f, x_ij    ~  Likelihood(f_i(x_ij))     [data]
Level 2:  f(x) | Ω         ~  GP(0, Ω ⊗ K)              [function prior]
Level 3:  Ω                ~  Prior(ν, C)                [task relation prior]
```

- MTGP stops at Level 2 (point estimate of Ω)
- MTGTP adds Level 3 (uncertainty over Ω)
- MTRL reformulates Level 2 as a **weight-space** prior: `W ~ MN(0, I, Ω)`

The weight-space view (MTRL) gives convexity. The function-space view (MTGP) gives non-parametric flexibility. They are mathematically equivalent for linear kernels.

> **Speaker notes:**
> - The equivalence between MTGP and MTRL under linear kernels connects these two lines of work. For RBF/nonlinear kernels, they diverge — GP gives richer expressiveness but loses convexity.
> - The Level 3 prior on Ω is what makes MTGTP Bayesian: it doesn't just find "the best" Ω, it maintains a posterior distribution over possible task covariance matrices.
> - For FYP context: if you wanted to extend wavCSE with task relation learning, the weight-space view (MTRL) is the natural fit — your task heads are linear layers on top of the shared embedding, and you'd add an Ω penalty on the head weight matrix.

## Slide 11: Connections to Other Approaches

**Vs. Low-Rank (2.2):**
- Low-rank: `W ≈ LSᵀ` with L ∈ ℝᵈˣʳ, r < m (low-dimensional latent basis)
- Task relation: W is full rank, but Ω couples columns
- Equivalence: when Ω = Sᵀ S (S is low-rank), the MTRL regularizer reduces to a low-rank penalty
- **Takeaway:** task relation learning subsumes low-rank as a special case

**Vs. Task Clustering (2.3):**
- Clustering: hard assignment — each task belongs to exactly one group
- Task relation: soft, continuous pairwise scores
- Clustering is more interpretable; task relation is more flexible

**Vs. Feature Learning (2.1):**
- Feature learning + task relation can be combined: shared encoder (feature-based) + MTRL penalty on task heads (parameter-based)
- This is the architecture Long et al. (2017) uses for deep MTL

> **Speaker notes:**
> - The relationship to low-rank is formally proven in the paper (problem 12 ↔ problem 21 equivalence). Both can be derived from the same matrix-variate normal prior with different constraints on Ω.
> - The practical implication: if you expect tasks to form clear clusters, use task clustering (more efficient, more interpretable). If task similarity is a spectrum with no clear boundaries, use task relation learning.
> - For the FYP: wavCSE currently uses EW (feature-based only). Adding an MTRL-style regularizer on the task heads would be a natural extension — you'd get quantitative evidence of KS↔SID↔ER relationships.

## Slide 12: Summary

| Aspect | Details |
|--------|---------|
| **What it learns** | Pairwise task covariance matrix Ω from data |
| **Key advantage** | No pre-specified task structure — continuous, gradable similarities |
| **Central method** | MTRL — convex, parallelizable, interpretable Ω |
| **Computational cost** | O(m²) parameters in Ω (mitigated by ℓ₁ sparsity) |
| **Deep learning extension** | Tensor-variate normal prior on parameter tensors |
| **Interpretability** | High — Ω can be visualized as a task affinity heatmap |
| **When to use** | When task similarity is continuous, not discrete; when interpretable task structure matters; when tasks have varying amounts of data |

> **Speaker notes:**
> - Section 2.4 covers roughly 15 core papers plus extensions. The methods build on each other cleanly: MTGP → MTGTP → MTRL → sparse/high-order/feature-level variants.
> - For the FYP project specifically: this section gives you the theoretical foundation for moving beyond equal weighting. MTRL would let you learn whether KS helps SID more than SID helps KS — asymmetric, quantitative, learned from data.
> - The main practical barrier for deep MTL: the O(m²d²) complexity of full MTRL on neural network weights. The tensor-variate extension (Long et al. 2017) and low-rank Ω (Yang et al. 2013) are the workarounds.
> - Open problem mentioned in the survey: none of these methods automatically detect or exclude outlier tasks — a task that's genuinely unrelated will still get a learned Ω value, and if it's non-zero, it will degrade performance for all tasks. This connects to your FYP focus on task imbalance.
