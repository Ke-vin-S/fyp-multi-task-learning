# Presentation: 2.4 — Task Relation Learning Approach

> From: Zhang & Yang, "A Survey on Multi-Task Learning", IEEE TKDE 2022

---

## Slide 1: What Question Does This Approach Answer?

**"How similar are my tasks, and can I learn that from data instead of guessing?"**

- Earlier MTL: someone tells you "KS and SID are similar, ER is different" — and you hard-code that into the model
- Task Relation Learning: the model figures out the similarities **by itself** from training data
- Learns a concrete number for each pair of tasks: how much should their parameters resemble each other?

---

## Slide 2: The Big Idea

```
Task A data  ──→  learn w_A    ┐
Task B data  ──→  learn w_B    ├──→  also learn Ω (which pairs are similar?)
Task C data  ──→  learn w_C    ┘
```

**Intuition**: if Task A and Task B are truly related, their optimal parameters (w_A, w_B) should be close. The model *discovers* this closeness from data, rather than us asserting it upfront.

---

## Slide 3: A Simple Analogy

Imagine 3 students (KS, SID, ER) studying for the same exam. Each has their own textbook (task-specific data).

- If two students **share notes** (high task relation) → they converge to similar answers because they've pooled their knowledge
- If two students **study completely different topics** (low task relation) → sharing notes would actually confuse them

Task Relation Learning answers: **which students should share notes, and how much?**

## Slide 4: Historical Evolution — Two Eras

### Era 1: Task Relations are GIVEN (pre-2007)

| Method | What's Given | How It Works |
|--------|-------------|--------------|
| [69, 70] | "All tasks are equally similar" | Pull every task's parameters toward the group average |
| [71, 72] | A similarity score for each pair | Pull w_i closer to w_j based on that given score |
| [75] | A tree/hierarchy of tasks | Parent tasks regularize child tasks |

**Problem**: You rarely know task similarities in advance. Guessing wrong hurts performance.

### Era 2: Task Relations are LEARNED (2007+)

The model treats task similarity as another parameter to optimize.

## Slide 6: Method 1 — MTGP (Bonilla et al., 2007)

**Core idea**: Use a Gaussian Process with a shared covariance structure.

### Two levels of covariance:

1. **Between data points** (same task): `k(x, x')` — standard GP kernel. If two audio clips sound similar, their labels should be similar.

2. **Between tasks**: A matrix `V` where `V_ip` = how much task `i` and task `p` covary.

### The combined kernel:
```
cov( f_task_i(x),  f_task_p(x') ) = V_ip  ×  k(x, x')
                                    ↑            ↑
                              task relation    data similarity
```

### How V is learned:
- Put a prior on the function values: `f ~ N(0, Σ)` where Σ encodes V
- Compute the marginal likelihood of the data given V
- Optimize V to maximize that likelihood

**Analogy**: V is like saying "being good at Math and Physics tend to go together" — it's a single number learned from all student scores that captures that tendency.

## Slide 7: Method 2 — MTRL (Zhang & Yeung, 2010/2012)

**The central paper of this approach.** Transforms the idea into a clean optimization problem.

### The prior on parameters:
```
W  ~  Matrix-Normal( mean=0,  row_covariance=I,  column_covariance=Ω )
```
- W: all task parameters stacked as columns (d features × m tasks)
- Ω: the `m × m` **task covariance matrix** — this is what we learn

### What "Matrix-Normal" means intuitively:
Each task's parameter vector `w_i` is a random draw. If `Ω_ij` is large, `w_i` and `w_j` tend to be similar because they come from a shared distribution.

### The optimization problem:
```
minimize    Training_Loss(W)
  W, Ω
            +  λ₁ · ||W||²_F                 (don't let weights get too large)
            +  λ₂ · tr( W · Ω⁻¹ · Wᵀ )      (penalize similar tasks for being different)

subject to  Ω ≻ 0           (Ω must be a valid covariance — positive definite)
            tr(Ω) ≤ 1       (control overall scale)
```

### How the regularizer works:

`tr(W · Ω⁻¹ · Wᵀ)` = sum over all task pairs (i,j) of: `(w_i's distance from zero) × (Ω⁻¹_ij) × (w_j's distance from zero)`

- If `Ω_ij` is large → `Ω⁻¹_ij` is small → low penalty → w_i and w_j can differ
- If `Ω_ij` is small → `Ω⁻¹_ij` is large → high penalty → w_i and w_j forced to be similar

Wait — that seems backwards. Let me re-explain properly.

**Correct intuition**: Think of Ω as a *precision* matrix (inverse covariance). When `Ω⁻¹_ij` is large, it means task i and task j are tightly coupled — if w_i moves, w_j should move similarly. The penalty `tr(W Ω⁻¹ Wᵀ)` is **large** when tasks that should be similar (high Ω⁻¹_ij) have very different parameters.

## Slide 8: MTRL — What Ω Tells You

After training, Ω is an `m × m` matrix:

```
         KS     SID    ER
    KS [ 0.3    0.25   0.05  ]
    SID[ 0.25   0.4    0.10  ]
    ER [ 0.05   0.10   0.35  ]
```

- **Diagonal** (0.3, 0.4, 0.35): each task's own variance — how much that task's parameters are allowed to vary
- **Off-diagonal** (0.25 = KS↔SID, 0.05 = KS↔ER): task relationship strength

**Reading this**: KS and SID are related (0.25), ER is quite independent from both (0.05, 0.10).

**Important**: The raw Ω is a **covariance** (scale-dependent). To interpret the strength, convert to **correlation**:
```
corr(KS, SID) = 0.25 / sqrt(0.3 × 0.4) = 0.72    ← strong
corr(KS, ER)  = 0.05 / sqrt(0.3 × 0.35) = 0.15   ← weak
```

## Slide 9: Method 3 — High-Order Relations (Zhang & Yeung, 2013)

**Limitation of MTRL**: Ω only captures **pairwise** relations (task A ↔ task B).

**Extension**: `(WᵀW)^t ~ Wishart(0, Ω)` where t > 1

- t = 1: pairwise relations (standard MTRL)
- t = 2: captures three-way relations (KS, SID, ER might all be related as a group in a way that pairwise can't capture)
- t = 3: four-way relations, etc.

**Intuition**: Three students might not be similar pairwise (each pair has different strengths), but as a group of three they form a study cohort that works well together. Standard MTRL would miss this.

## Slide 10: Method 4 — Local Task Relations (Zhang, 2012)

**Problem with all previous methods**: They learn **global** task relations — one number per task pair for the entire model.

**This method**: Learns relations for **k-nearest-neighbor** classification. Each prediction is a weighted vote:

```
prediction for a test point = sum of (task_similarity_ij × data_similarity × neighbor_label)
                                  over all k nearest neighbors
```

The `task_similarity_ij` matrix S is learned, and it's **asymmetric**:
- `S_AB` = how much task B helps task A (might not equal `S_BA`)
- A difficult task with little data can borrow heavily from an easy task, but not vice versa

---

## Slide 11: Asymmetric Relations (Lee et al., 2016)

**Key insight**: Task help is not always mutual.

- Easy task → Hard task: large benefit (share a lot of information)
- Hard task → Easy task: small benefit (the hard task has noisy, unreliable parameters)

The model learns an asymmetric matrix A where:
```
w_i  ≈  Σ_j  A_ij · w_j     (task i's parameters ≈ weighted sum of other tasks')
```

This allows **directional** knowledge transfer: easy tasks lend strength to hard ones.

## Slide 13: Strengths & Weaknesses

| Strengths | Weaknesses |
|-----------|------------|
| Data-driven: no need to guess which tasks are related | Computationally heavier than simple EW |
| Interpretable: Ω matrix shows exactly which tasks help each other | Harder to scale to many tasks (`m × m` matrix grows quadratically) |
| Convex (MTRL): guaranteed to find the global optimum | Most implementations assume linear models |
| Flexible: can be symmetric or asymmetric | For deep networks, requires tensor extensions (more complex) |

### Our tasks: KS, SID, ER, IC

| What we could do | What it tells us |
|-----------------|------------------|
| Run MTRL on our 4 tasks | Get a 4×4 Ω matrix: which tasks naturally share information? |
| Compare Ω with LibMTL dynamic weights | Does the *learned* static relation match the *computed* per-step gradient weighting? (e.g., does GradNorm consistently up-weight the same tasks that MTRL says are related?) |
| Check if high Ω_ij correlates with task conflict | Are strongly-related tasks also the ones with conflicting gradients? |

### Where we are now:
- wavCSE: feature-based MTL, equal weighting — **no task relation learning**
- LibMTL weighting methods: dynamic per-step weighting — **task relations computed, not learned** (they don't produce a persistent Ω matrix)
- Task Relation Learning: would give us a **static, interpretable task similarity matrix**

## Slide 15: One-Slide Takeaway

Task Relation Learning answers: **"Which tasks should share parameters, and by how much?"**

- **Before**: you had to guess
- **Now**: the model learns it from data, producing a concrete similarity matrix Ω
- **Key paper**: MTRL by Zhang & Yeung — clean convex optimization, interpretable output
- **For our FYP**: this gives us a principled way to measure *why* and *how much* speech tasks (content, speaker, emotion) benefit from joint training — complementing the dynamic weighting approaches in LibMTL
