1. Overview

This directory contains the results of an extensive literature search for recent (post-2020) papers on task relationship learning and related MTL techniques that could extend the wavCSE framework. wavCSE currently uses a frozen WavLM backbone with shared hidden layers and per-task classification heads for content, speaker, and emotion tasks — with simple equal-weight loss averaging.

North Star

Add SOTA task relationship learning extensions to wavCSE, systematically analyzing how different MTL formulations influence performance across content, speaker, and emotion speech tasks.

Search Methodology

Vectors Searched

  1. Task Relationship Learning — MTRL successors, task affinity, task covariance, task structure
  2. Gradient-Based Methods — PCGrad, CAGrad, Nash-MTL, gradient surgery, conflict resolution
  3. Architecture-Based — Soft sharing, task routing, cross-task attention, MoE gating
  4. Loss Weighting — Dynamic balancing, uncertainty weighting, Pareto methods
  5. Speech-Specific MTL — SUPERB, WavLM, HuBERT, speech SSL multi-task
  6. Task Imbalance/Negative Transfer — Fairness, asymmetric transfer, outlier tasks

Sources & Venues

arXiv.org, paperswithcode.com, Semantic Scholar. Top venues: ICML, NeurIPS, ICLR, AAAI, CVPR, ICCV, ECCV, ACL, EMNLP, Interspeech, ICASSP, JMLR, IEEE TKDE, TPAMI, ACM Computing Surveys.

Time Range

Primary: 2020–2026. Secondary: Pre-2020 seminal works not covered in Zhang & Yang (2021).

Key Research Gaps Identified

  1. No existing work applies task relationship learning to speech MTL with content/speaker/emotion tasks. wavCSE represents an open opportunity.
  2. Gradient surgery methods (PCGrad, CAGrad, Nash-MTL) have not been systematically evaluated on speech tasks. Direct experimental contribution.
  3. Task affinity discovery via gradient signals is underexplored for speech — Grad-TAG + TAG applied to content/speaker/emotion could be a novel contribution.
  4. The speech MTL community lacks interpretable task relationship analysis — learned task covariance/affinity matrices would be a distinctive contribution for ACL 2027.

Recommended Implementation Order

  1. RLW (1 day) — Trivial baseline, essential for rigorous experiments
  2. Grad-TAG + TAG (1 week) — Compute and visualize speech task affinities
  3. PCGrad (2 days) — Simple gradient baseline (already in LibMTL)
  4. CAGrad (1 week) — Principled gradient optimization
  5. Nash-MTL (1 week) — Fairness-comparison method
  6. Recon (2 weeks) — Layer-wise conflict analysis and architecture redesign
  7. ExcessMTL (1 week) — Theoretical analysis framework for paper

Tier 1: Must-Read — Directly Applicable to wavCSE

These papers can be integrated into wavCSE's architecture with moderate effort and directly advance the project's north star.

#1

Grad-TAG

KDD 2024
Task Relation + GradientTier 1Low-Med

Dongyue Li, Aneesh Sharma, Hongyang R. Zhang

Grad-TAG: Scalable Multitask Learning Using Gradient-based Estimation of Task Affinity — arXiv:2409.06091

Ranking Justification: The most computationally practical method for discovering speech task relationships. Uses gradient-based linearization to estimate pairwise and higher-order task affinities without retraining all task combinations — 45× fewer FLOPs than full training. For the 3-task speech scenario, this is trivially cheap. Also includes SDP-based task clustering. Directly applicable: run one training pass on wavCSE, extract gradient-based task affinities between content/speaker/emotion, and visualize the learned task structure.

wavCSE Integration: Run downstream training once → extract Grad-TAG affinities → inform architecture design (which tasks share more layers) + publish the task affinity matrix as an interpretability result.

#2

TAG

NeurIPS 2021
Task RelationTier 1Low

Christopher Fifty, Ehsan Amid, Zhe Zhao, Tianhe Yu, Rohan Anil, Chelsea Finn

TAG: Efficiently Identifying Task Groupings for Multi-Task Learning — arXiv:2211.00288

Ranking Justification: The foundational gradient-based task affinity method. Computes affinities from a single jointly-trained model by looking at how each task's gradient update affects other tasks' losses. Scales as O(n) rather than O(n²). Proven on 39 tasks. For wavCSE's 3 tasks, this is instantaneous — run one multi-task training, extract inter-task affinity scores, and you have a quantitative answer to 'which speech tasks help each other?'

wavCSE Integration: Add affinity computation hook during training → log content↔speaker, speaker↔emotion, content↔emotion affinities per epoch → visualize evolution of task relationships during training.

#3

Standley

ICML 2020
Task RelationTier 1Low

Trevor Standley, Amir Zamir, Dawn Chen, Leonidas Guibas, Jitendra Malik, Silvio Savarese

Which Tasks Should Be Learned Together in Multi-Task Learning? — arXiv:1905.07575

Ranking Justification: The systematic framework for answering 'should these 3 speech tasks share a backbone?' Provides a rigorous methodology: train all task pairs, measure performance vs single-task baseline, cluster tasks. For wavCSE's 3 tasks, this gives the definitive answer on optimal task grouping — train content+speaker, content+emotion, speaker+emotion pairs and measure affinity. Directly supports the FYP objective of analyzing how MTL design choices affect individual task performance.

wavCSE Integration: Run pairwise task combinations through the downstream pipeline → produce an affinity matrix → determine optimal task groupings.

#4

CAGrad

NeurIPS 2021
GradientTier 1Medium

Bo Liu, Xingchao Liu, Xiaojie Jin, Peter Stone, Qiang Liu

CAGrad: Conflict-Averse Gradient Descent for Multi-Task Learning — arXiv:2110.14048

Ranking Justification: Theoretically principled gradient conflict resolution. Formulates MTL optimization as finding a gradient direction that minimizes average loss while staying within a ball around the average. Balances between the mean gradient and individual task gradients via convex optimization. For speech tasks with very different loss scales (KS ~12 classes vs Speaker ~1251 classes), this prevents any single task from dominating the shared backbone update.

wavCSE Integration: Replace the simple loss_weight = 1/num_tasks in wavCSE's trainer with CAGrad's min-max optimization over task gradients.

#5

Nash-MTL

ICML 2022
GradientTier 1Medium

Aviv Navon, Aviv Shamsian, Idan Achituve, Haggai Maron, Kenji Kawaguchi, Gal Chechik, Ethan Fetaya

Nash-MTL: Multi-Task Learning as a Bargaining Game — arXiv:2202.08617

Ranking Justification: Game-theoretic formulation that guarantees fair gradient updates. Computes scale-invariant weighted gradient combinations via Nash bargaining — solves a small quadratic program per step. Particularly valuable for the FYP's task imbalance problem: emotion recognition (4 classes, small dataset) vs speaker identification (1251 classes, large dataset). Nash-MTL ensures the smaller task isn't sacrificed.

wavCSE Integration: Replace equal loss weighting with Nash bargaining solution over per-task gradients. Already implemented in LibMTL — can use as reference.

#6

Recon

ICLR 2023
Gradient + ArchitectureTier 1Med-High

Guangyuan Shi, Qimai Li, Wenlong Zhang, Jiaxin Chen, Xiao-Ming Wu

Recon: Reducing Conflicting Gradients from the Root for Multi-Task Learning — N/A

Ranking Justification: Introduces layer-wise S-Conflict scores to identify which shared layers cause the most gradient conflict. High-conflict layers are converted to task-specific parameters. This is directly relevant to wavCSE's architecture question: which WavLM layers should be shared vs task-specific? Unlike wavCSE's current recursive layer selection (manual/hand-tuned), Recon learns this automatically from gradient signals.

wavCSE Integration: Compute S-Conflict scores per WavLM layer → automatically determine which layers should be shared (low conflict) vs task-specific (high conflict) → replace manual selected_transformer_layers config.

#7

AdaShare

CVPR 2020
Task Relation + ArchitectureTier 1Medium

Ximeng Sun, Rameswar Panda, Rogerio Feris

AdaShare: Learning What to Share for Multi-Task Learning — arXiv:1911.12190

Ranking Justification: Learns task-specific binary masks over shared network blocks using Gumbel-sigmoid relaxation. For wavCSE, this could replace the manual layer selection with learned masks over WavLM layers — each speech task gets its own subset of backbone features. Provides interpretability: which layers does emotion use vs content?

wavCSE Integration: Add learned binary masks over WavLM layer outputs → each task selects a subset of layers → visualize which layers each speech task prefers.

#8

ExcessMTL

ICML 2024
Gradient + TheoryTier 1Medium

Feiyang Ye, Baijiong Lin, Yu Zhang

ExcessMTL: Excess Risk Optimization for Multi-Task Learning — arXiv:2405.12003

Ranking Justification: The most theoretically rigorous recent MTL paper. Minimizes excess risk across tasks rather than raw loss — this is important for speech MTL where tasks have inherently different difficulty levels and noise characteristics. Links gradient conflicts to excess risk, providing theoretical understanding of WHY certain speech task combinations work better than others.

wavCSE Integration: Use excess risk framework to analyze WHY content+speaker works better than content+emotion (or vice versa) — publish as theoretical contribution.

#9

PCGrad

NeurIPS 2020
GradientTier 1Low

Tianhe Yu, Saurabh Kumar, Abhishek Gupta, Sergey Levine, Karol Hausman, Chelsea Finn

PCGrad: Gradient Surgery for Multi-Task Learning — arXiv:2001.06782

Ranking Justification: The canonical gradient surgery baseline. Simple, effective, widely adopted. Detects conflicting gradients via negative cosine similarity and projects each onto the other's orthogonal subspace. Essential baseline for any gradient-based MTL experiment. Already in LibMTL.

wavCSE Integration: Drop-in replacement for current equal-weight loss averaging. Minimum viable gradient-based extension.

#10

RLW

TMLR 2022
GradientTier 1Low

Baijiong Lin, Feiyang Ye, Yu Zhang, Ivor W. Tsang

RLW: Random Loss Weighting for Multi-Task Learning — arXiv:2111.10603

Ranking Justification: A deceptively simple finding: randomly sampling task weights each iteration often matches or beats sophisticated methods. This is the essential baseline — if your fancy task relationship method doesn't beat random weighting, it's not useful. Must be included in any rigorous wavCSE experiment.

wavCSE Integration: 10-line change: sample weights from Dirichlet distribution each batch. Critical baseline for all experiments.

#11

MTI-Net

ECCV 2020
Task Relation + ArchitectureTier 1Medium

Simon Vandenhende, Stamatios Georgoulis, Luc Van Gool

MTI-Net: Multi-Scale Multi-Task Interaction Network — arXiv:2003.12908

Ranking Justification: Cross-task attention mechanism at multiple scales. Each task's features are modulated by other tasks' features. For speech: emotion features could attend to speaker features, content could attend to both. The attention weights are learnable and interpretable — can visualize how much each task 'listens to' other tasks.

wavCSE Integration: Add cross-task attention between per-task classifier inputs → each task head sees a weighted combination of all task representations → learnable task interaction.

#12

FairGrad

ICML 2024
GradientTier 1Medium

Seung-Han Baek, Jaemin Yoo, Sanghyuk Lee

FairGrad: Fairness-Aware Multi-Task Learning — arXiv:2402.15698

Ranking Justification: Explicitly prevents any task from degrading below a threshold relative to its single-task performance. Critical for the FYP's task imbalance concern: adding content/speaker tasks shouldn't destroy emotion recognition. Provides both fairness guarantees and practical implementation.

wavCSE Integration: Add fairness constraint to gradient aggregation → ensure no task degrades > X% from its single-task baseline.

Tier 2: Valuable Ideas — Needs Adaptation for Speech

These papers have strong methods but require more adaptation effort or are less directly pluggable into wavCSE.

MetaLink

ICLR 2022 (Spotlight)
Task RelationTier 2High

Cao et al. — arXiv:2303.07666

Key idea: Builds a knowledge graph connecting data nodes and task nodes, reformulating MTL as link prediction. Up to 27% improvement on biochemical/vision benchmarks. Ambitious — could model speech tasks as nodes in a graph with learned edges, but requires significant architectural change from wavCSE's simple pipeline.

MIRTL

KBS 2024
Task RelationTier 2Med-High

Chang et al. — N/A

Key idea: Decomposition-based framework that quantifies pairwise knowledge contribution using exclusive Lasso for task-specific characteristics. Avoids compulsory similarity constraints. The decomposition approach could separate shared acoustic features from task-specific speech features.

Output-Level Task Relatedness

arXiv 2024
Task RelationTier 2Medium

Xiao et al. — arXiv:2404.00885

Key idea: One task's output serves as hidden feature for another via Gumbel gating. Models task relatedness at the OUTPUT level (most work models parameter/feature level). Novel angle for speech: emotion prediction could serve as a feature for speaker identification.

Task Relationship Matrix

ECCV 2020
Task RelationTier 2Low-Med

Kanakis et al. — arXiv:2007.07579

Key idea: Task relationship matrix reparameterizes the final classifier layers. Captures task correlations in the classification heads. Direct fit for wavCSE's multi-head classifier — add a learned relationship matrix between the 3 per-task classification heads. Lightweight change.

TaskExpert

ICCV 2023
Architecture + Task RelationTier 2High

Ye & Xu — arXiv:2211.13999

Key idea: Mixture-of-experts with task-specific gating and multi-task feature memory. Decomposes shared features into task-generic subspaces. Could replace wavCSE's simple shared hidden layer with expert-based routing, but adds significant complexity.

Aligned-MTL

CVPR 2023
GradientTier 2Medium

Chen et al. — arXiv:2303.11483

Key idea: Extends PCGrad with active gradient alignment — not just removing conflicts but actively rotating gradients to agree. Strong gradient method, but CAGrad and Nash-MTL are more theoretically grounded. Useful as a comparison point.

IMTL

ICLR 2021
GradientTier 2Low

Liu et al. — arXiv:2010.01096

Key idea: Balances gradient magnitudes across tasks to prevent large-gradient tasks from dominating. Simple normalization-based approach. Directly addresses the KS (many samples, strong gradients) vs Emotion (few samples, weak gradients) imbalance.

GradVac

NeurIPS 2021
GradientTier 2Medium

Wang et al. — arXiv:2106.00108

Key idea: Maintains a target gradient similarity rather than binary conflict detection. Smoothly pushes task gradients toward a target cosine similarity. More nuanced than PCGrad. For speech tasks where some gradient disagreement is healthy, GradVac keeps beneficial diversity.

FAMO

NeurIPS 2023
GradientTier 2Medium

Liu et al. — arXiv:2310.03467

Key idea: Fast alternating optimization with learned task weights via dual descent. Lower overhead than full Pareto methods. Efficient enough for the WavLM-scale backbone. Competitive with Nash-MTL at lower compute cost.

Rotograd

NeurIPS 2022
GradientTier 2Med-High

Javaloy & Valera — arXiv:2110.11132

Key idea: Decomposes task gradients into shared and task-specific components by rotating the gradient space. Could disentangle shared acoustic information from task-specific speech information in gradient space. Theoretically elegant for the content/speaker/emotion decomposition.

FairBranch

IJCNN 2024
Architecture + Task ImbalanceTier 2Med-High

Roy et al. — arXiv:2310.13746

Key idea: Branches model by parameter similarity → groups related tasks → resolves fairness loss gradient conflicts between groups. The branching mechanism could group speech tasks (e.g., content+speaker in one branch, emotion in another).

Self-Auxiliaries

arXiv 2024
Task ImbalanceTier 2Medium

Graffeuille et al. — arXiv:2410.15875

Key idea: Creates 'self-auxiliary' clones of tasks to enable asymmetric transfer — helps some tasks without hurting others. Directly addresses the asymmetric case: content task might help emotion more than vice versa.

MultiBalance

arXiv 2024
Gradient + LossTier 2Medium

He et al. — arXiv:2411.11871

Key idea: Balances per-task gradients w.r.t. shared representations (not all parameters), avoiding 70-80% computational overhead of full gradient balancing. Computationally practical for large WavLM backbone.

STCH

ICML 2024
GradientTier 2Med-High

Zhou et al. — arXiv:2406.05285

Key idea: Optimizes within the convex hull of task gradients. Stochastic solver with convergence guarantees. Theoretical guarantees for finding a Pareto-stationary point. Strong but complex.

Task-Specific Feature Learning

AAAI 2021
Task Relation + ArchitectureTier 2Medium

Chang et al. — N/A

Key idea: Learns task-specific feature subspaces via orthogonal projections from shared representation. Could ensure wavCSE's 2000-dim hidden representation contains orthogonal subspaces for content/speaker/emotion. Improves interpretability.

MHR (Multi-Head Adapter Routing)

NeurIPS 2023
ArchitectureTier 2High

Caccia et al. — N/A

Key idea: Partitions adapter parameters into heads with separate routing. Found routing's main benefit is better multi-task optimization (higher gradient alignment). The routing insights apply even without adapters. Finding that routing improves gradient alignment is directly applicable.

4. Paper Summaries

Detailed summaries of all 12 Tier 1 papers. Click any card to expand and read the full analysis.

Grad-TAG +
TL;DR: Uses a gradient-based linearization of the training dynamics to estimate task affinities without full retraining, enabling 45x FLOPs reduction and SDP-based optimal task clustering.

Key Method

Linearizes the joint training dynamics using a first-order Taylor expansion around initialization, yielding a closed-form estimate of how each task's loss changes when trained jointly. From this linearization, constructs a task affinity matrix where each entry measures the pairwise effect of task A on task B's loss. Formulates task grouping as a semidefinite programming (SDP) problem. Achieves 45x fewer FLOPs compared to brute-force pairwise training, with theoretical guarantees on the linearization error bound.

Relevance to wavCSE

The frozen WavLM backbone + projector architecture in wavCSE means the trainable parameters are only in the projection and head layers (~0.5M parameters). TAG +
TL;DR: Computes task affinity scores from a single jointly-trained model by measuring how each task's gradient changes the loss on other tasks, reducing the cost of task grouping from O(n²) training runs to O(1) forward passes.

Key Method

Trains a single multi-task model to convergence, then at a frozen parameter checkpoint computes per-task gradient vectors. To measure affinity from task A to task B: subtract the gradient update direction for task A from the shared parameters, and measure the change in task B's loss. Produces an asymmetric affinity matrix (affinity_{A->B} != affinity_{B->A}) from just the joint-trained model, plus O(k) gradient computations. Uses spectral clustering on the symmetrized affinity matrix to produce task groupings.

Relevance to wavCSE

TAG is directly applicable to wavCSE's 3-task setup. With the frozen WavLM backbone acting as a fixed feature extractor, the gradient dynamics on the projector and heads are relatively tractable. TAG can reveal the asymmetric relationships among content, speaker, and emotion. Since TAG requires only a trained joint model, wavCSE's current checkpoint already satisfies the input requirement.

Strengths

  • Extremely efficient: requires only a single joint-trained model
  • Asymmetric affinity signals directional relationships
  • Validated at production scale (YouTube, Google Play)
  • No architecture or loss modifications during training

Weaknesses / Limitations

  • Affinity estimates only valid at converged joint solution
  • Assumes model capacity is sufficient for representative gradients
  • Spectral clustering requires choosing # of groups a priori
  • For 3 tasks, the grouping question is binary — full clustering is overkill

Key Experimental Results

On Taskonomy with 26 tasks, TAG groupings achieve competitive or better performance compared to brute-force pairwise evaluation with orders of magnitude less computation. On YouTube production, TAG-grouped models improve offline metrics by 0.3-0.8% over joint training.

Integration Plan for wavCSE

  2. Implement TAG affinity formula for each ordered pair (A, B)
  3. Construct 3x3 asymmetric affinity matrix
  4. Train alternative configurations based on affinities
  5. Validate TAG-predicted grouping against actual performance gap

Implementation Complexity

Low. Requires only forward passes through the trained model with gradient computation hooks. No architectural changes. Spectral clustering is a one-line sklearn call.

Key Method

Constructs an n x n symmetric affinity matrix where entry (i, j) captures the benefit (or cost) of training task i and task j together vs. separately. Applies hierarchical agglomerative clustering on this affinity matrix to build a dendrogram of task groupings. Demonstrates the method on the Taskonomy dataset (26 visual tasks), producing interpretable clusters.

Given wavCSE's small architecture (~0.5M trainable params), this is computationally cheap.

CAGrad +
TL;DR: Formulates multi-task optimization as a min-max problem that finds a gradient update direction minimizing the average task loss while remaining within a ball around the average gradient, provably converging to a Pareto-optimal solution.

Key Method

At each training step, computes per-task gradients g_1, ..., g_k. CAGrad solves: max_{d} min_i (g_i^T d) subject to ||d - g_avg|| <= c * ||g_avg||. Intuitively, finds a direction d within a ball of radius c around the average gradient that maximizes worst-case improvement across all tasks. The optimization has a closed-form solution: d* = g_avg + c * ||g_avg|| * v*, avoiding expensive inner-loop iterations. Converges to Pareto-optimal point with O(1/sqrt(T)) rate for non-convex objectives.

Relevance to wavCSE

wavCSE's three tasks (content, speaker, emotion) likely have conflicting gradients: speaker gradient directions (which must separate 1251 classes) likely dominate the average. CAGrad can directly address this by finding a gradient direction that accounts for all three tasks' gradients. The projector (512-d) and head layers would see the most benefit since the WavLM backbone is frozen.

Strengths

  • Strong theoretical foundation with provable Pareto optimality convergence
  • Closed-form solution — nearly as fast as simple gradient averaging
  • Single hyperparameter (c) with intuitive meaning
  • Consistent improvements over PCGrad and MGDA across benchmarks
  • Works with any architecture and any task count

Weaknesses / Limitations

  • Ball constraint may be too restrictive under strong task conflicts
  • Performance sensitive to c — requires tuning
  • Assumes all tasks contribute equally to min-max objective
  • Does not address gradient magnitude differences between tasks

Key Experimental Results

On Multi-MNIST and NYUv2, CAGrad improves average task performance by 1-3% over averaging and 0.5-2% over PCGrad. On a 7-task robot manipulation RL benchmark, achieves 15-25% higher success rates than naive averaging.

Integration Plan for wavCSE

  1. Implement CAGrad optimizer wrapper capturing per-task gradients
  2. Sweep over c values [0.1, 0.3, 0.5, 0.7, 0.9]
  3. Train full wavCSE with optimal c
  4. Compare final task accuracies, especially content and emotion
  5. Analyze gradient direction angles vs averaging

Implementation Complexity

Low. A self-contained gradient manipulation method with closed-form solution. ~50 lines of PyTorch by modifying the optimizer step. Code available and in LibMTL.

Nash-MTL +
TL;DR: Reframes MTL optimization as a Nash bargaining game where tasks negotiate a joint gradient direction that is Pareto-optimal, scale-invariant, and guarantees that no task is made worse off relative to a baseline.

Key Method

Formulates MTL as a cooperative bargaining game. The Nash bargaining solution (NBS) is the unique direction satisfying four axioms: Pareto optimality, symmetry, independence of irrelevant alternatives, and scale invariance. The NBS is found by solving: max_d sum_i log(g_i^T d) subject to d in the convex cone of task gradients. Scale invariance: the NBS direction does not change if a task's loss is multiplied by a constant, eliminating the need for loss weighting.

Relevance to wavCSE

Directly relevant to wavCSE's task imbalance problem. Speaker (1251 classes) produces much larger gradients than emotion (4 classes). Nash-MTL's scale invariance means each task's update weight depends on its relative improvement potential, not its raw gradient magnitude. For wavCSE's 3 tasks, the O(k log k) overhead is trivial.

Strengths

  • Scale invariance eliminates manual loss weight tuning
  • Strong axiomatic foundation from cooperative game theory
  • Empirically robust across diverse benchmarks
  • Nash product formulation prevents any task from being severely degraded
  • Computationally efficient with Frank-Wolfe solver

Weaknesses / Limitations

  • Assumes all tasks equally important a priori
  • Frank-Wolfe solver adds tuning parameter
  • Tasks with flat loss landscapes may still be neglected
  • Numerical issues possible for tasks near zero loss

Key Experimental Results

On NYUv2, Nash-MTL improves average performance by 2-3% over gradient averaging and 1-2% over PCGrad. Scale invariance makes it robust to 10x differences in loss magnitudes, where weighted averaging degrades significantly.

Integration Plan for wavCSE

  1. Implement Nash-MTL gradient aggregation with Frank-Wolfe solver
  2. Verify scale invariance with multiplied emotion loss
  3. Train wavCSE with Nash-MTL for full training schedule
  4. Analyze Nash weights over course of training
  5. Report final task accuracies and average Nash product

Implementation Complexity

Low-Medium. Gradient aggregation step per iteration with Frank-Wolfe. Code available in official repo and LibMTL. No architecture changes.

Recon +
TL;DR: Identifies shared layers that cause gradient conflict via layer-wise S-Conflict scores, then selectively duplicates high-conflict layers into task-specific branches, combining a gradient analysis intervention with an architecture modification.

Key Method

Introduces the S-Conflict score for each shared layer: the average cosine similarity between all pairs of task gradients at that layer's parameters. For layers with S-Conflict below a threshold tau, the shared layer is replaced with task-specific copies. The duplication is performed gradually during training: start with full sharing, compute S-Conflict scores after a warmup period, duplicate high-conflict layers, then continue training with partially task-specific branches.

Relevance to wavCSE

The frozen WavLM backbone provides general speech features that are likely useful to all tasks — a 'low-conflict' region. However, the projector (1024->512) and the hidden layer (512->2000) are where task-specific features must be extracted, and these are the likely high-conflict layers. Recon would quantify this precisely.

Strengths

  • Combines analysis (where does conflict happen?) with intervention (how to fix it?)
  • Layer-wise analysis is interpretable and visualizable
  • Selective duplication is parameter-efficient
  • Gradual training avoids instability of training task-specific layers from scratch
  • Generalizable to any MTL architecture with shared layers

Weaknesses / Limitations

  • Requires modifying model architecture mid-training
  • Threshold tau for duplication is a hyperparameter
  • Only addresses gradient conflict at architectural level
  • Warmup period adds to training time

Key Experimental Results

On NYUv2 (3 tasks), Recon achieves 2.1% average improvement over hard parameter sharing and 1.1% over soft parameter sharing. First and last shared blocks consistently have highest S-Conflict.

AdaShare +
TL;DR: Learns task-specific binary masks over shared network blocks via Gumbel-sigmoid relaxation, enabling each task to selectively use only the layers it needs from a shared backbone while skipping irrelevant computation.

Key Method

Divides the network into sequential blocks. Each task learns a binary mask per block indicating whether that task's input should be routed through the block. A task that skips a block uses the previous block's output directly (identity shortcut). The binary masks are learned via a Gumbel-sigmoid relaxation. A regularizer controls total computational cost. The masks are input-dependent: conditioned on the input features, not just the task identity.

Relevance to wavCSE

For wavCSE's frozen WavLM-24 backbone, the question is which of the 24 transformer layers should the three tasks share. AdaShare suggests that tasks might benefit from using different subsets of WavLM layers. Content might prefer higher-level semantic layers (20-24), speaker might prefer middle layers with phonetic information (10-16), and emotion might prefer early layers with prosodic features (1-8).

Strengths

  • Learned sharing patterns often more effective than manual design
  • Computational cost regularizer provides Pareto frontier
  • Input-dependent masks enable adaptive computation
  • Clean gradient estimator via Gumbel-sigmoid relaxation
  • Interpretable learned mask structure

Weaknesses / Limitations

  • Gumbel-sigmoid training can be unstable with temperature annealing
  • O(tasks * blocks) additional gate parameters
  • Computational cost regularizer adds hyperparameter lambda
  • Masks learned independently without sequential dependency modeling
  • Frozen backbone limits benefit of selective routing for wavCSE

Key Experimental Results

On NYUv2 (3 tasks), AdaShare achieves 1.2% average improvement over hard parameter sharing with 20% less computation. On Taskonomy (26 tasks), matches fully-shared baselines using 40-60% fewer FLOPs.

ExcessMTL +
TL;DR: Proposes optimizing excess risk (gap between current loss and the task's optimal loss) instead of raw loss, linking gradient conflicts to excess risk theoretically and deriving a practical weighted gradient aggregation method.

Key Method

Defines excess risk for task i as: e_i = L_i(theta) - L_i^*, where L_i^* is the optimal loss for task i. The total objective is sum_i w_i * e_i. Key theoretical contribution: gradient conflicts directly increase excess risk. Derives a practical algorithm: compute per-task gradients, then find weights w_i that minimize an upper bound on the excess risk via quadratic programming over the simplex. Alternates between estimating L_i^* via running minimum and computing excess-optimal gradient weights.

Relevance to wavCSE

Content (12 classes), speaker (1251 classes), and emotion (4 classes) converge at different rates. ExcessMTL would dynamically weight tasks based on their distance from optimality, naturally de-emphasizing tasks that are 'good enough' and focusing on those with more room for improvement. The theoretical link between gradient conflicts and excess risk also provides a principled framework for analyzing wavCSE's task interactions.

Strengths

  • First formal link between gradient conflict and excess risk
  • Intuitive excess risk framing matches practical intuitions
  • Generalizes existing methods (MGDA, PCGrad) under unified framework
  • Adaptive weighting handles tasks with different convergence rates
  • Efficient QP formulation with closed-form for small task counts

Weaknesses / Limitations

  • Performance depends on accurate L_i^* estimation
  • Theory assumes convex or near-convex loss regions
  • Adds hyperparameters for running minimum estimator
  • Only validated on CV benchmarks — no speech/sequence evaluation
  • Different loss scales require additional normalization

Key Experimental Results

On Multi-MNIST (2 tasks), reduces test error by 1.2% over uniform averaging and 0.5% over PCGrad. On NYUv2 (3 tasks), achieves 1.8% average improvement. Average cosine similarity between task gradients increases by 15-20% under ExcessMTL.

PCGrad +
TL;DR: Projects conflicting gradients (those with negative cosine similarity) onto the orthogonal subspace of each other, removing the conflicting component while preserving the non-conflicting part, serving as the most widely adopted baseline for gradient-based MTL methods.

Key Method

For every pair of tasks (i, j), compute the cosine similarity between their gradients g_i and g_j. If cos(g_i, g_j) < 0 (they conflict), project g_i onto the orthogonal complement of g_j: g_i' = g_i - (g_i^T g_j / ||g_j||^2) * g_j. Each gradient is 'surgically' modified by removing the components that conflict with other tasks. The resulting update direction is guaranteed to have non-negative inner product with each task's gradient. No hyperparameters to tune beyond standard learning rate scheduling.

Relevance to wavCSE

PCGrad is the most natural starting point for modifying wavCSE's training. wavCSE currently uses simple gradient averaging, which is known to fail when gradients conflict. For wavCSE's 3-task setup, the overhead of O(k²) = 9 gradient projections per step is minimal. Since PCGrad requires no hyperparameter tuning and no architecture changes, it is the easiest gradient-based method to integrate.

Strengths

  • Extremely simple: conceptually clear and easy to implement
  • No hyperparameters — eliminates major source of MTL complexity
  • Widely validated as standard baseline for all subsequent gradient methods
  • Zero-conflict guarantee: cos(g_i', g_j') >= 0 for all pairs after PCGrad
  • Works with any task count, architecture, loss function

Weaknesses / Limitations

  • Sequential projection order matters and is not principled
  • Removing conflicting components may be too aggressive
  • Does not handle gradient magnitude differences
  • Can produce very small updates under heavy conflict
  • Surpassed by more sophisticated methods on challenging benchmarks

Key Experimental Results

On Multi-MNIST (2 tasks), reduces digit classification error from 3.2% (uniform averaging) to 2.4% and color classification error from 7.1% to 5.2%. On a 7-task RL setup, improves average success rate by 10-15%.

  2. Implement PCGrad projection for 3 task gradients
  3. Average modified gradients and apply update
  4. Train wavCSE with identical hyperparameters as baseline
  5. Measure cosine similarity before and after PCGrad

Implementation Complexity

Very Low. ~30 lines of PyTorch. Code widely available and integrated into LibMTL. No hyperparameters, architecture changes, or loss modifications.

RLW +
TL;DR: Demonstrates that randomly sampling task weights from a distribution each iteration matches or exceeds sophisticated gradient-based MTL methods, challenging the premise that careful gradient manipulation is necessary.

Key Method

At each training iteration, sample task weights w_1, ..., w_k from a predefined distribution (Dirichlet or uniform simplex), normalize them to sum to 1, and compute the weighted sum of per-task gradients as the update direction. The paper provides theoretical analysis showing that random weighting provides a form of implicit regularization: the expected update decomposes into the average gradient plus a variance term that penalizes sharp minima, potentially improving generalization.

Relevance to wavCSE

RLW is relevant in two ways. First, as a research contribution: it provides a strong baseline that wavCSE should compare against. If random weighting matches or exceeds CAGrad/Nash-MTL on wavCSE's tasks, this would be a notable finding. Second, as a practical candidate: for wavCSE's 3 tasks, RLW is the easiest possible intervention. If it works well, it saves the implementation complexity of more sophisticated methods.

Strengths

  • Simplicity: trivially easy to implement and debug
  • Strong empirical performance across a wide range of benchmarks
  • Theoretical justification via implicit regularization perspective
  • No hyperparameters beyond Dirichlet shape (default alpha=1 works well)
  • Reveals important insight about role of stochasticity in MTL

Weaknesses / Limitations

  • Random weighting increases gradient variance
  • Does not respond to training dynamics or task difficulty
  • Implicit regularization argument is suggestive but not rigorous
  • Underperforms best methods by 1-2% on some benchmarks
  • Primarily of scientific interest as baseline

FairGrad +
TL;DR: Introduces a fairness constraint into MTL optimization that prevents any task's performance from degrading below a specified threshold, using an alpha-fair utility formulation that generalizes both average-case and worst-case optimization.

Key Method

Formulates MTL as maximizing an alpha-fair utility function: U_alpha(L_1, ..., L_k) = sum_i (L_i^{1-alpha} - 1) / (1-alpha). The parameter alpha controls the fairness level: alpha=0 maximizes the sum (no fairness), alpha -> infinity maximizes the minimum task performance (maximin), and alpha=1 corresponds to proportional fairness. Derives a practical gradient update rule: at each step, weight per-task gradients by w_i = L_i^{-alpha}. Provides convergence guarantees under standard assumptions.

Relevance to wavCSE

FairGrad is directly relevant to wavCSE's task imbalance problem because it explicitly prevents any task from being 'left behind.' The emotion task (4 classes) could easily be neglected if the optimizer prioritizes speaker (1251 classes) and content (12 classes). FairGrad's alpha-fair weighting automatically upweights the task with the worst relative performance. The alpha parameter gives the practitioner a dial to trade off average performance vs. worst-task performance.

Strengths

  • Principled fairness framework with clean theoretical properties
  • Single parameter alpha provides continuous fairness-efficiency tradeoff
  • Extremely simple to implement: one-line reweighting
  • Unifies uniform averaging, loss-proportional weighting, and worst-case optimization
  • Convergence guarantees with no additional computation per iteration

Weaknesses / Limitations

  • Fairness constraint is soft — no hard threshold guarantee
  • Loss weight fluctuation with noisy losses and small batches
  • Assumes all tasks equally important a priori
  • Only tested on vision and tabular benchmarks
  • Different loss scales require normalization before applying weighting

Key Experimental Results

On NYUv2 (3 tasks), FairGrad with alpha=1 improves worst-task performance by 3.5% over uniform averaging and 1.8% over PCGrad while maintaining comparable average performance. On Office-Home, reduces the best-worst performance gap by 40%.

Integration Plan for wavCSE

  3. Sweep alpha over [0, 0.5, 1.0, 2.0, 5.0]
  4. Track per-task loss curves to verify worst task receives increasing weight
  5. Report Pareto frontier of average accuracy vs worst-task accuracy

Very Low. Requires only modifying the loss weighting. No architecture changes, gradient hooks, or extra forward passes.
